# Seata TCC 模式迁移方案（纯新增，不动原有）

## 原则

- **原有接口全部保留不动**：create()、cancel()、deduct()、restore() 等
- **全部新增**：新 Controller、新方法、新 Feign 接口、新 DTO
- **向下兼容**：AT 模式和 TCC 模式可并存，前端可选择调用

## 核心改造点

### 1. 数据模型改造（仅新增字段）

**hotel_product_spec 表** - 新增冻结库存字段（不影响现有逻辑）：
```sql
ALTER TABLE hotel_product_spec ADD COLUMN frozen_stock INT NOT NULL DEFAULT 0 COMMENT '冻结库存(TCC)';
```

**hotel_order 表** - 不改表结构，复用 status 字段：
- 0=已取消, 1=已完成, 2=待确认（TCC Try 阶段创建）

### 2. RPC 层新增（sca-rpc 模块，不动现有 StockFeignClient/OrderFeignClient）

新增文件：

**StockTccClient.java** - 新增 TCC 库存 Feign 接口：
```java
@FeignClient(name = "sca-stock", path = "/inner/stock/tcc")
public interface StockTccClient {
    @PostMapping("/try")
    Result<Object> tryFreeze(@RequestBody StockFreezeRequest request);
    @PostMapping("/confirm/{xid}")
    Result<Object> confirm(@PathVariable String xid);
    @PostMapping("/cancel/{xid}")
    Result<Object> cancel(@PathVariable String xid);
}
```

**OrderTccClient.java** - 新增 TCC 订单 Feign 接口：
```java
@FeignClient(name = "sca-order", path = "/inner/order/tcc")
public interface OrderTccClient {
    @PostMapping("/try")
    Result<String> tryCreate(@RequestBody OrderCreateRequest request);
    @PostMapping("/confirm/{xid}")
    Result<Object> confirm(@PathVariable String xid);
    @PostMapping("/cancel/{xid}")
    Result<Object> cancel(@PathVariable String xid);
}
```

**StockFreezeRequest.java** - 新增 DTO（同 StockDeductRequest 结构）

### 3. 库存服务新增（sca-stock，不动 StockController）

新增 **StockTccController.java**（`/inner/stock/tcc`）：

| 接口 | 方法 | 操作 |
|------|------|------|
| POST /try | tryFreeze | `stock -= qty`, `frozen_stock += qty`（乐观锁） |
| POST /confirm/{xid} | confirm | `frozen_stock -= qty`（确认扣减） |
| POST /cancel/{xid} | cancel | `stock += qty`, `frozen_stock -= qty`（释放冻结） |

新增 Mapper SQL（在 HotelProductSpecMapper 中追加方法）：
- `freezeStock(specId, qty)` - 冻结库存
- `confirmFrozen(specId, qty)` - 确认扣减
- `cancelFrozen(specId, qty)` - 释放冻结

新增 **tcc_stock_record 表**（记录冻结操作，供 Confirm/Cancel 查询）：
```sql
CREATE TABLE tcc_stock_record (
  id VARCHAR(64) PRIMARY KEY,
  xid VARCHAR(128) NOT NULL COMMENT '全局事务ID',
  spec_id VARCHAR(64) NOT NULL,
  quantity INT NOT NULL,
  status TINYINT DEFAULT 0 COMMENT '0=冻结 1=已确认 2=已取消',
  created_time DATETIME DEFAULT CURRENT_TIMESTAMP
);
```

### 4. 订单服务新增（sca-order，不动 OrderController）

新增 **OrderTccController.java**（`/inner/order/tcc`）：

| 接口 | 方法 | 操作 |
|------|------|------|
| POST /try | tryCreate | 创建订单 status=2（待确认），返回 orderId |
| POST /confirm/{xid} | confirm | 根据 xid 找到订单，status=2->1 |
| POST /cancel/{xid} | cancel | 根据 xid 找到订单，status=2->0 |

新增 Mapper 方法：
- `confirmOrderByXid(xid)` - 确认订单
- `cancelOrderByXid(xid)` - 取消订单

hotel_order 表新增 xid 字段（记录全局事务 ID，供 Confirm/Cancel 查找）：
```sql
ALTER TABLE hotel_order ADD COLUMN xid VARCHAR(128) DEFAULT NULL COMMENT 'Seata全局事务ID(TCC)';
```

### 5. TM 编排 - 新增接口（sca-web，不动现有 create/cancel）

**HotelOrderController 新增方法**：

```java
@PostMapping("/tcc")
public Result<Object> createByTcc(@Valid @RequestBody CreateOrderRequest request) {
    // 使用 Seata GlobalTransaction 手动编排 TCC
    GlobalTransaction tx = GlobalTransactionContext.getCurrentOrCreate();
    try {
        tx.begin(60000, "create-order-tcc");
        // 1. Try: 冻结库存
        stockTccClient.tryFreeze(freezeRequest);
        // 2. Try: 创建待确认订单（传 xid）
        orderTccClient.tryCreate(orderRequest);
        // 3. 全局提交 -> 自动触发 Confirm
        tx.commit();
        return Result.success();
    } catch (Exception e) {
        // 全局回滚 -> 自动触发 Cancel
        tx.rollback();
        return Result.fail(e.getMessage());
    }
}
```

新增 TCC 售后取消接口：
```java
@PutMapping("/tcc/cancel/{id}")
public Result<Object> cancelTccOrder(@PathVariable String id) {
    // 已确认订单的售后取消，直接 restore 库存
}
```

## 实施步骤

| 阶段 | 操作 | 涉及模块 |
|------|------|----------|
| Phase 1 | DDL：spec 表加 frozen_stock，order 表加 xid，建 tcc_stock_record | Database |
| Phase 2 | 新增 StockFreezeRequest DTO + StockTccClient + OrderTccClient | sca-rpc |
| Phase 3 | 新增 StockTccController + Mapper 方法 | sca-stock |
| Phase 4 | 新增 OrderTccController + Mapper 方法 | sca-order |
| Phase 5 | HotelOrderController 新增 createByTcc() 和 cancelTccOrder() | sca-web |
| Phase 6 | 编译验证 + 测试 TCC 下单/取消流程 | 全模块 |

## 风险与注意事项

1. **空回滚**：Cancel 可能在 Try 未执行时被调用 -> tcc_stock_record 表检查记录
2. **悬挂**：Cancel 先于 Try 到达 -> Try 检查是否已取消，若是则拒绝
3. **幂等**：Confirm/Cancel 需支持重复调用 -> 基于 status 字段判断
4. **xid 传递**：Try 时传 xid 给下游，Confirm/Cancel 通过 xid 查找记录
